# OPTIMUM — разработка музыкального приложения нового поколения

## 1. Главная задача

Ты — ведущий разработчик, системный архитектор, UI/UX-дизайнер и инженер музыкальных рекомендательных систем.

Создай полноценное кроссплатформенное музыкальное приложение **OPTIMUM** для Windows, Android и iOS.

OPTIMUM объединяет музыкальный проигрыватель, персональную библиотеку, интеллектуальные рекомендации, импорт плейлистов и совместное прослушивание музыки с друзьями.

**ГЛАВНЫЙ ПРИОРИТЕТ: КАЧЕСТВО РАБОТЫ, А НЕ СКОРОСТЬ РАЗРАБОТКИ.**

Не стремись завершить проект за минимальное количество запросов или итераций.

Лучше потратить больше времени на архитектуру, интерфейс, тестирование и исправление ошибок, чем создать много нестабильных функций.

Не используй временные заглушки вместо настоящей функциональности без явного согласования.

Каждый завершённый этап должен быть работоспособным, протестированным и документированным.

## 2. Главное нововведение — OPTIMUM TOGETHER

**Совместное прослушивание музыки с друзьями в реальном времени — центральная функция приложения.**

Реализуй систему музыкальных комнат.

### Создание комнаты

Пользователь может:

- Создать приватную музыкальную комнату.
- Пригласить друзей по ссылке или коду.
- Подключиться к комнате другого пользователя.
- Увидеть список участников.
- Назначить название комнаты.
- Управлять настройками доступа.
- Покинуть комнату без завершения прослушивания остальных участников.

### Синхронное воспроизведение

Все участники должны слышать одну и ту же композицию максимально синхронно.

При этом:

- Нажатие Play запускает воспроизведение у участников.
- Pause останавливает воспроизведение.
- Переключение композиции синхронизируется.
- Перемотка синхронизируется.
- Новые участники подключаются к текущей позиции композиции.
- При задержках соединения система корректирует рассинхронизацию.
- После потери интернета приложение восстанавливает состояние комнаты.

Реализуй синхронизацию через серверное время, WebSocket, оценку задержки сети и коррекцию позиции воспроизведения.

Предусмотри плавную коррекцию небольших расхождений, чтобы не создавать постоянных слышимых скачков.

**Важно:** синхронизируй команды и позиции воспроизведения. Не передавай защищённое аудио одного пользователя другим участникам. Каждый слушатель должен иметь законный доступ к выбранной композиции через свою библиотеку или разрешённый сервис.

### Совместная очередь

Реализуй:

- Добавление песен в общую очередь.
- Голосование за следующую композицию.
- Перестановку треков при наличии разрешений.
- Историю прослушивания комнаты.
- Возможность сохранять совместные плейлисты.
- Режим, в котором управление доступно только создателю комнаты.
- Режим демократического управления.

### Социальные возможности

Добавь:

- Список друзей.
- Приглашения в друзья.
- Отображение статуса доступности с настройками приватности.
- Список активных музыкальных комнат друзей.
- Текстовый чат внутри комнаты.
- Реакции на музыку.
- Возможность отключить приглашения.
- Блокировку пользователей и жалобы на нарушения.

Голосовой чат пока не обязателен, но архитектура должна позволять добавить его в будущем.

### Режим совместной «Моей волны»

Создай специальный алгоритм, который объединяет музыкальные предпочтения участников комнаты.

Например:

- 40% рекомендаций на основе общих интересов.
- 30% на основе вкусов первого участника.
- 30% на основе вкусов второго участника.

Это пример, а не фиксированная формула. Разработай справедливую систему, учитывающую всех участников, их предпочтения и разнообразие рекомендаций.

Добавь возможность выбирать режим:

- Общие вкусы.
- Новые открытия.
- Максимальное разнообразие.
- Спокойная атмосфера.
- Энергичная музыка.

## 3. Дизайн — OPTIMUM COSMIC

Интерфейс должен быть современным, дорогим на вид, минималистичным и космическим.

### Цветовая палитра

Основные цвета:

- Глубокий чёрный: #050507.
- Чёрный графит: #101014.
- Тёмно-серый: #19191F.
- Основной текст: #F5F5F7.
- Второстепенный текст: #92929C.

Белый используй умеренно: для текста, отдельных акцентов, активных элементов и мягкого свечения.

Избегай яркого разноцветного оформления.

### Космическая тематика

Используй:

- Медленно движущиеся звёзды.
- Небольшие светящиеся частицы.
- Глубину пространства.
- Плавные градиенты.
- Тонкие световые линии.
- Размытые туманности.
- Мягкое свечение активных элементов.
- Эффекты параллакса.
- Плавные переходы между экранами.

**Интерфейс не должен быть статичным.**

Он должен ощущаться живым даже тогда, когда пользователь ничего не нажимает.

Однако анимации должны быть ненавязчивыми, не мешать чтению и не перегружать видеокарту или аккумулятор телефона.

### Реакция на музыку

Добавь музыкальную визуализацию:

- Волны звука.
- Плавное движение частиц.
- Изменение свечения.
- Реакцию фона на ритм при наличии доступных аудиоданных.
- Плавное затухание эффектов при остановке музыки.

Если анализ аудио недоступен из-за ограничений сервиса, используй нейтральные анимации, не имитирующие точный анализ ритма.

### Интерфейс совместного прослушивания

Это должен быть один из самых красивых экранов приложения.

Размести:

- Крупную обложку текущей композиции.
- Анимированное космическое окружение.
- Аватары участников.
- Состояние синхронизации.
- Общую очередь.
- Управление воспроизведением.
- Кнопку приглашения друзей.
- Чат.
- Настройки комнаты.

Визуально передай ощущение, что друзья находятся в одном музыкальном пространстве, даже если физически находятся далеко.

### Анимации

Используй качественные переходы, а не случайные декоративные эффекты.

Обязательно:

- Плавное открытие страниц.
- Анимированные кнопки.
- Реакции при наведении мыши.
- Анимации добавления музыки.
- Плавное появление карточек.
- Переход мини-плеера в полноэкранный режим.
- Анимации подключения участников.
- Плавное изменение состояния комнаты.

Поддерживай настройку уменьшения движения для пользователей, которым это необходимо.

## 7. АЛЬБОМЫ НАСТРОЕНИЯ

Каждые пять часов автоматически формируй несколько персональных музыкальных подборок.

Примеры:

- Космическая ночь.
- Потерянная галактика.
- Энергия звёзд.
- Тихая орбита.
- За пределами атмосферы.
- Новые миры.

Каждая подборка должна иметь:

- Уникальное название.
- Обложку.
- Описание.
- 15–30 композиций.
- Время создания.
- Возможность сохранения.

Учитывай музыкальную историю и настроение, выбранное пользователем.

Сохраняй старые подборки в архиве.

Фоновая генерация должна работать независимо от того, открыто приложение или нет, с корректной обработкой ошибок и часовых поясов.

## 9. Архитектура

Используй:

- Flutter — Windows, Android, iOS.
- Dart — клиент.
- just_audio — аудио.
- audio_service — фоновое воспроизведение.
- just_audio_media_kit — Windows.
- FastAPI — сервер.
- WebSocket — синхронизация музыкальных комнат.
- Supabase — авторизация и база данных.
- SQLite — локальная библиотека.
- Redis — при необходимости для координации комнат и масштабирования.
- MusicBrainz — музыкальные метаданные.
- Troi / ListenBrainz — рекомендации.

Для комнат реализуй авторитетное серверное состояние и последовательную обработку команд.

Покрой тестами:

- Подключение участников.
- Одновременное воспроизведение.
- Паузы.
- Перемотку.
- Переключение треков.
- Потерю соединения.
- Повторное подключение.
- Передачу управления.
- Права участников.
- Синхронизацию при сетевых задержках.

Измеряй фактическое рассогласование воспроизведения. Не обещай идеальную синхронизацию при любых сетевых условиях.

## 12. Качество важнее скорости

Это обязательное правило проекта.

- Не спеши.
- Не пропускай тестирование.
- Не упрощай архитектуру только ради скорости.
- Не создавай фиктивные функции.
- Не скрывай ошибки.
- Не выдавай макет за готовое приложение.
- Проверяй производительность.
- Следи за использованием оперативной памяти.
- Оптимизируй анимации.
- Проверяй интерфейс на разных разрешениях.
- Проверяй работу при слабом интернете.
- Учитывай особенности мобильных устройств.
- Не допускай потери пользовательских данных.
- Делай резервные копии перед опасными изменениями.

После каждого этапа:

1. Проведи проверку кода.
2. Запусти тесты.
3. Исправь обнаруженные ошибки.
4. Проверь основные пользовательские сценарии.
5. Обнови документацию.
6. Сохрани рабочую версию в Git.
7. Подготовь отчёт на русском языке.

Создай README.md, ROADMAP.md, CHANGELOG.md, ARCHITECTURE.md и AGENTS.md.

Веди разработку последовательно. Если задача требует больше времени, разбивай её на небольшие законченные этапы.

**Итоговая цель: OPTIMUM должен ощущаться как качественный самостоятельный музыкальный продукт, а не учебный проект или копия существующего приложения.**

Начни с проверки окружения, архитектуры, плана разработки и создания первого рабочего прототипа для Windows. Сохраняй возможность дальнейшей сборки Android и iOS.
