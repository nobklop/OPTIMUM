# Импорт музыки по ссылкам — уточнённый сценарий

Пользовательский результат: ссылка на трек или плейлист Яндекс Музыки, Spotify
или SoundCloud → записи в OPTIMUM → воспроизведение в приложении → сохранение
доступного для скачивания аудио для офлайна. Метаданные или внешняя ссылка сами
по себе не считаются выполненным импортом аудио. В 0.2.1 этот модуль ещё отсутствует.

## Подтверждённые границы сервисов

| Сервис | Доступ и следующий шаг |
|---|---|
| SoundCloud | Официальное API поддерживает resolve URL, треки/плейлисты и streams. Регистрация приложения требует Artist Pro; нужны Client ID/Secret. `access` различает playable/preview/blocked; скачивание разрешается только при `downloadable` и предоставленном `download_url`. |
| Spotify | Web API предоставляет каталог/плейлисты и управление воспроизведением. Полное воспроизведение требует разрешённой интеграции и подходящего аккаунта/платформы. Обычный URL трека не является доступным для скачивания MP3. |
| Яндекс Музыка | Офлайн-файлы зашифрованы и доступны в приложениях Яндекса. Для встроенного воспроизведения/импорта нужен отдельно подтверждённый разрешённый способ интеграции. Общий скачиватель по ссылке не заявляется. |

Первичные источники (19 октября 2026):
[SoundCloud API guide](https://developers.soundcloud.com/docs/api/guide),
[регистрация API](https://developers.soundcloud.com/docs/api/register-app),
[OpenAPI](https://developers.soundcloud.com/docs/api/explorer/api.json),
[Spotify Web API](https://developer.spotify.com/documentation/web-api),
[Яндекс: офлайн](https://yandex.ru/support/music/ru/listening/listening-offline).

При реализации SoundCloud использовать актуальный `/tracks/{track_urn}/streams`:
в текущем OpenAPI старое поле `stream_url` помечено deprecated и preview-only.
Preview не выдаётся за полную запись. Ключи приложения остаются на сервере;
они не включаются в Flutter binary, Git, JSON backups и диагностические сообщения.
Живой API ещё не подключён; наличие аккаунта/приложения уточняется у пользователя.

## Архитектура и критерии следующего законченного этапа

1. Отдельный provider adapter: строгая проверка домена/типа URL, canonical id,
   разрешение короткой ссылки только у её провайдера; защита backend от SSRF.
2. OAuth/защищённое хранение токенов, повторное использование токенов, лимиты,
   безопасное обновление и disconnect. Секреты не запрашиваются через текст чата.
3. Версионированная миграция с backup: источник, canonical id, permalink, metadata,
   доступность и локально сохранённый файл. Старые локальные записи и JSON v1 сохраняются.
4. Трек/плейлист импортируются атомарно с исходным порядком и статусами недоступных
   записей. Повторный импорт по canonical id не создаёт дубликаты; названия не
   используются как доказательство одинаковой записи. Сохранение атрибуции источника.
5. Воспроизведение получает свежий разрешённый stream; истекающие CDN URL не являются
   постоянными идентификаторами. 401/403/preview/geo-block дают честное состояние.
6. Разрешённый download пишется во временный файл с лимитом размера, затем проверяется,
   атомарно перемещается в управляемое хранилище и связывается с библиотекой. Прерывание
   не оставляет ложную отметку «Скачано». Поток не сохраняется как download без разрешения.
7. Реальная проверка: ссылка → корректный трек/плейлист → звук → повторный импорт →
   разрешённое скачивание → воспроизведение после отключения сети → перезапуск.
   Негативные сценарии: закрытая запись, нет прав, недоступная страна, истёкший токен,
   лимит API, отмена/сбой скачивания и нехватка места.

До этой проверки не добавлять работающую на вид кнопку, которая создаёт только
название или открывает сервис вместо обещанного воспроизведения внутри OPTIMUM.
