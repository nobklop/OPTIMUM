# Резервные копии OPTIMUM 0.4

В настройках доступны **Сохранить копию** и **Восстановить из JSON**.
Формат `optimum-library` v3: пути и метаданные треков, избранное, плейлисты с
порядком треков, до 5000 записей истории, настройка уменьшения движения,
сохранённые ссылки и связи со скачанными файлами. Аудио, обложки и cookies
веб-плееров не включаются. V3 также включает источник и упорядоченные ссылки
сервисных плейлистов, включая повторные позиции. Старые JSON v1/v2 читаются;
OPTIMUM 0.3 не читает JSON v3 и SQLite v4.

Восстановление объединяет данные одной транзакцией. Текущие названия, метаданные
и настройки не перезаписываются; избранное объединяется. Плейлисты сопоставляются
по устойчивому ключу или URL источника, ссылки — по canonical URL. Повторное восстановление не
создаёт дубликаты. Отсутствующая связь со скачанным файлом может быть восстановлена,
существующая не заменяется. Удаление локального трека очищает эту связь.
Это объединение, а не точный откат библиотеки к старому состоянию.
При объединении сервисного состава существующий порядок остаётся, отсутствующие
вхождения ссылок дописываются в порядке снимка; число повторов не растёт при
повторном восстановлении. Свежий перенос из сервиса после подтверждения отдельно
заменяет состав плейлиста, сохраняя его пользовательское название.

Максимум 32 МБ, 50000 треков, 5000 плейлистов, 5000 записей истории и 10000 ссылок.
Типы, пути, URL и ссылки на отсутствующие записи проверяются до изменения базы.
JSON содержит личные пути, ссылки и историю; приложение само его никуда не отправляет.
Для переноса нужны сами аудиофайлы по тем же путям. Скачанные файлы находятся в
application support/Downloads; их необходимо копировать отдельно.

## Миграция и полный откат базы

OPTIMUM 0.4 использует SQLite v4. Закройте старые экземпляры перед запуском.
До обновления v1/v2/v3 `VACUUM INTO` создаёт согласованный снимок
`library.db.before-v4-<UTC microseconds>.db` рядом с базой. Ошибка копирования
прерывает открытие до миграции; ошибка миграции откатывает транзакцию.
Ранее созданные before-v2/v3 копии сохраняются. Путь базы показан в настройках.

Для отката закройте **все** экземпляры OPTIMUM. Сохраните текущую папку базы
целиком отдельно, включая возможные -wal/-shm. В исходной папке уберите текущую
базу и её WAL/SHM; скопируйте нужный автоматический снимок под именем library.db
и запустите соответствующую старую версию. Не оставляйте WAL/SHM другой базы
рядом с восстановленным файлом. Изменения после снимка останутся только в
сохранённой папке. Сам установщик защищает от случайного понижения версии.

Проверены обновления v1→v4 и v3→v4, целостность снимков, откат при ошибке,
восстановление старых JSON и v3, 1295 позиций с повторами, связи файлов и сохранность аудио.
Тесты: client/test/backup_test.dart, music_links_test.dart, playlist_transfer_test.dart.
