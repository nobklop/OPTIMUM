# Архитектура OPTIMUM

## Границы первой версии

Flutter/Dart клиент для Windows, Android, iOS; локальная SQLite; `just_audio`
с `just_audio_media_kit` на Windows. FastAPI отделён от воспроизведения.
Первый прототип работает без аккаунта и без передачи аудио на сервер.
Статус подтверждённых сборок и проверок: `docs/VERIFICATION.md`.

## Клиент

`lib/data` — схема SQLite, транзакции, импорт метаданных в отдельном isolate.
`lib/playback` — единственный экземпляр аудиоплеера и сериализация загрузок.
`lib/ui` — адаптивный Cosmic, реальное состояние библиотеки/плеера.
В 0.2.1 фон содержит 184 звезды и пять распределённых туманностей, HeroSkyPainter
добавляет детали на всю ширину главного блока. Облака используют две общие кэшированные
текстуры; все декоративные движения периодичны относительно общего 90-секундного clock.
С 0.2.2 clock обновляется на каждом vsync. Прежнее округление до 30 Гц давало
неравномерный шаг на этом экране; profile-замеры и тесты описаны в docs/PERFORMANCE.md.
`lib/together` — расчёт времени/коррекции, независимо от Flutter UI и транспорта.

SQLite хранит идентификаторы, пути, метаданные, избранное, плейлисты, историю
и настройки. Аудиофайлы пользователя остаются по выбранным путям; удаление
из библиотеки не удаляет оригинал. Пропавший файл даёт видимую ошибку.
Изменения библиотеки транзакционные; foreign keys включены; миграции версионируются.
Схема v2 добавляет стабильный backup_key плейлиста (случайные 128 бит), поэтому
одноимённые плейлисты не сливаются. Перед миграцией v1→v2 `VACUUM INTO` создаёт
согласованную копию исходной базы. JSON export/restore — метаданные без аудио:
полная валидация до транзакции, merge без удаления и без перезаписи текущих метаданных.
История сортируется по времени прослушивания, чтобы старый backup не вытеснял
свежие прослушивания. Формат и откат описаны в `docs/BACKUPS.ru.md`.
Обложки читаются отдельно от массового сканирования, чтобы не раздувать память.
Сканирование не следует symbolic links. Повторный импорт одного пути идемпотентен.

В 0.3 SQLite v3 добавляет music_links отдельно от локальных tracks: canonical URL,
пользовательское имя, nullable download_path с ON DELETE SET NULL. До обновления
v1/v2 сохраняется VACUUM INTO before-v3; ошибка миграции откатывает транзакцию.
JSON v2 включает ссылки и связи с локальными файлами; v1 продолжает читаться.
music_link.dart строго разбирает URL; link_resolver.dart раскрывает известные share
домены без API-ключей, с allowlist/HTTPS/лимитами. WebView2 загружает официальные
embed-адреса; для новых Яндекс UUID/track-only — страницу сервиса. Веб-профиль отдельный,
привилегированного JS bridge нет, permissions запрещены, popups отключены.
Вход на экран останавливает libmpv; выход уничтожает WebView. Provider-очередь не
смешивается с локальной. Прямые HTTPS-аудиофайлы скачиваются последовательно с
тайм-аутами/лимитами/сигнатурой во временный файл, затем атомарно переименовываются
и импортируются. Секретные потоки и cookies сервисов не извлекаются.

ServiceAccount задаёт только официальные website/login/library URL; UI открывает
их в том же профиле WebProfile, что и embeds. Account-mode отображает origin/path
без query, кнопки входа/библиотеки/назад/обновить. Popups в этом режиме направляются
в текущее окно для штатного website login; новые отдельные окна не создаются.
Пароли, cookies и localStorage сайтов не читаются приложением и не входят в JSON.
Нет фиктивного connected-статуса: успешный вход отображает сам сайт. Сессии сайтов
не являются Supabase/OPTIMUM-аккаунтом, и личные лайки/плейлисты не копируются в SQLite.

Мобильный фон и lock-screen добавляются через `audio_service` после проверки
нативных manifest/entitlements и реальных устройств. Наличие iOS runner не означает
проверку сборки: для этого необходимы macOS, Xcode и signing.

Windows-установщик Inno Setup размещает приложение в профиле пользователя, создаёт
ярлыки и uninstall entry. Обновления не затрагивают application support directory.
libmpv не входит в публичный EXE-установщик: загрузка из upstream с archive/DLL SHA-256
до установки. CRT — app-local. Release publisher сначала создаёт draft, загружает и
проверяет digest каждого asset, затем публикует. Credentials читаются только из GCM.

## Авторизация и серверное хранение (следующий этап)

Supabase Auth выдаёт JWT. FastAPI проверяет подпись через JWKS, issuer, audience,
expiry; идентификатор пользователя выводится из `sub`, а не из тела команды.
Refresh-токены хранятся в Keychain/Keystore/Windows Credential Manager.
Service-role key никогда не попадает в клиент.
PostgreSQL — источник истины для аккаунтов, связей, плейлистов и комнат.
RLS: владелец для личных строк; активное членство для комнат; серверные RPC
для передачи управления, голосования и приглашений. Каждая политика должна
иметь негативные тесты от второго пользователя до включения облачных функций.

В прототипе отсутствует облачная схема, которая могла бы создать ложное ощущение
готовой безопасности. HTTP API публикует только health и честные capabilities.

## OPTIMUM TOGETHER

Исполняемое серверное ядро: `backend/app/rooms.py`, тесты `backend/tests`.
Команды последовательно обрабатываются под lock комнаты. `expected_revision`
предотвращает потерянные обновления; `(user_id, command_id)` исключает повторное
применение при retry. Снимок содержит revision, server_ms, anchor_ms, позицию,
очередь, участников, владельца и голоса. В очереди только canonical recording id
и длительность. Нет байтов аудио, URL сервисов или локальных путей.

Старт назначается на server_now + 500 мс. Новый участник получает актуальный снимок.
Короткий disconnect не означает leave. После reconnect клиент повторно получает
снимок, проверяет доступность записи и только затем включает звук. При отсутствии
доступа отображается причина; комната продолжает работу для остальных.
Leave владельца передаёт управление старшему оставшемуся участнику.

План транспорта: WSS с аутентификацией до подписки; ограниченные размеры сообщений,
rate limit, очередь отправки на сокет, heartbeat, таймаут и slow-consumer eviction.
Сетевые отправки выполняются вне lock. Один actor комнаты — один писатель.
При нескольких процессах требуется Redis/actor routing и durable event log в PostgreSQL.
Локальный `asyncio.Lock` не даёт распределённой гарантии.
Вычислительный monotonic clock использует boot/session epoch; после рестарта
anchor пересоздаётся из durable position, никогда не читается как старое monotonic время.

## Коррекция синхронизации

Четыре времени ping: local send t0, server receive s1, server send s2, local receive t3.
RTT = (t3-t0)-(s2-s1); offset = ((s1-t0)+(s2-t3))/2.
Отрицательные, нечисловые, слишком медленные samples отбрасываются. Оценка берётся
по низколатентным samples, чтобы асимметрия очередей меньше влияла на offset.
Небольшой drift (до 40 мс) игнорируется, средний исправляется скоростью 0.98–1.02,
крупный (от 250 мс) — seek. После коррекции скорость возвращается к 1.
Реальная точность зависит от выхода аудиоустройства, декодера и сети. Метрики:
RTT p50/p95, offset uncertainty, абсолютный drift p50/p95, hard seek count,
buffer underruns, reconnect time. Цифры нельзя обещать до испытаний на устройствах.

## Рекомендации и альбомы (план)

Детерминированный explainable ranker: weighted genre/artist preferences, реакции,
недавние прослушивания и skips; diversity penalty, exploration slider. Cold start
использует явно выбранные интересы, а не случайность под видом персонализации.
Группа: средняя нормированная оценка + минимальная удовлетворённость участника;
round-robin exposure debt не позволяет одному участнику доминировать.
Troi/ListenBrainz подключаются адаптерами, MusicBrainz — metadata only с rate limit.

Подборки каждые 5 часов — серверный worker с UTC slot key `(user, slot, mood)`,
идемпотентной транзакцией, retry/backoff и архивом. Время пользователя конвертируется
только при отображении; DST не сдвигает интервалы. При каталоге <15 доступных треков
показывается недостаток материала, а не дублируются песни ради длины.

## Границы интеграций

Импорт плейлистов переносит metadata, сопоставляет recording id/ISRC/artist/title.
Платформенные адаптеры должны проверять актуальные API scopes/terms. Воспроизведение
только локальных разрешённых файлов или официально доступных источников.
DRM extraction, нелегальные загрузчики и пересылка защищённого аудио отсутствуют.

## Производительность

Один AudioPlayer; список треков ленивый; metadata в isolate; repaint звёзд изолирован.
Один общий clock для звёзд и hero-орбит; обновление медленного фона ограничено
30 разами в секунду, независимо от обновлений UI. Shader-туманности один раз
растеризуются в маленькие 256×256 текстуры; полноэкранный blur не используется.
Параллакс ограничен несколькими пикселями. Периодические функции дают непрерывный цикл.
Анимация отключается при reduced motion и скрытии/потере активности окна,
не требует точного анализа ритма.
Визуализация пока нейтральная. Не заявляем частоту кадров, расход батареи или RAM
без профилирования release-сборки. Будущие бюджеты проверяются на целевых устройствах.
